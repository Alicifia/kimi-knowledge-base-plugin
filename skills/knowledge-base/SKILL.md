# 本地知识库

把用户指定的本地目录变成真正的知识库：文档切块 → 向量化（CJK 单字+二元组 TF-IDF）→ SQLite 持久化 → 余弦相似度检索 + 文档关联。**零第三方依赖、零网络、零配置**，任何 Python 3.8+ 都能跑。

支持**多知识库**：所有库登记在全局注册表（`~/.kimi-work/knowledge-base.json`）里，可以按名称切换、一览全部库、或一次提问跨全部库统一检索。每个库的索引自包含在自己的目录里，互不影响，换机直接拷贝文件夹即可。

## 核心脚本

`scripts/kb.py`（相对于本 SKILL.md 所在目录）。一律用 `python scripts/kb.py <命令>` 调用（Windows 上 `python` 与 `python3` 均可，哪个能用用哪个）。

| 命令 | 作用 |
|---|---|
| `init --root <目录> [--name 别名]` | 指定本地知识库目录并初始化（不存在会自动创建），自动登记进注册表并设为当前激活库；别名默认用目录名 |
| `use --root <目录或名称>` | 在多个知识库之间切换，可直接用注册表里的名称 |
| `libraries` | 列出注册表里的全部知识库：名称、目录、文档/块数、是否当前激活、目录是否还在 |
| `forget <目录或名称>` | 从注册表注销某个知识库。**只删登记信息，不删目录里的任何文件**，随时可 init 登记回来 |
| `add <文件或目录> [...] [--strict]` | 导入文档并建索引；目录会递归扫描；重复 add 自动跳过未变化文件。`--strict`：任何文件读取失败立即退出（exit 2），用户说"失败就退出/不要部分导入"时必须加 |
| `remove <路径或标题> [...]` | 从库中移除文档 |
| `search "<问题或关键词>" [--top 8] [--per-doc] [--all]` | 向量检索，返回 JSON：相关块、所在文档、标题层级、相似度分数、摘要。`--all`：跨注册表内全部知识库统一检索，结果合并排序并标注来源库（`kb` 字段） |
| `related <路径或标题> [--top 5]` | 查某篇文档的关联文档：显式 `[[wikilink]]`/markdown 链接（双向）+ 向量相似文档 |
| `list` | 列出库内全部文档及块数 |
| `status` | 当前激活库、已登记库清单、文档/块/词表/链接统计 |
| `reindex` | 全量重建索引（文档被外部大量改动后用） |

## 支持格式

- 原生：`.md` / `.markdown` / `.txt`（按 Markdown 标题层级切块，保留标题路径作为上下文）
- 电子书：`.epub`、`.mobi`、`.azw3`、`.azw`（标准库直读；mobi 系为 PalmDOC 解压，双区段文件自动取正文最长的区段；**HuffCDIC 压缩的老 Kindle 文件不支持**，会明确报"HuffCDIC 压缩，暂不支持"）
- 可选：`.docx`（需环境里有 python-docx）、`.pdf`（需 pdfplumber）；缺库时会明确提示并跳过，不会报错中断

## 大库性能

检索是两级的：先用文档级向量预筛出候选文档，再在候选文档内做块级精排，几百本长篇小说的库也能秒回。索引按块存 TF，重建时不用重新分词。

## 使用流程

1. **首次使用**：用户给出目录 → `python scripts/kb.py init --root "<目录>"`。目录里已有的 md/txt 不会自动入库，需要接着 `add`。
2. **导入**：`python scripts/kb.py add "<目录或文件>"`。新文件、改动过的文件会自动更新索引。
3. **检索问答**：用户提问 → `search "<用户问题>"` → 从返回的 hit 里取 snippet 作答，**答案中注明出处文件**（`rel_path` + `heading`）。score < 0.05 的结果基本无关，忽略。
4. **关联探索**：用户问"这篇笔记和哪些相关" → `related <标题>`。
5. **多库**：用户可以给不同主题建多个库（如 `~/kb/工作`、`~/kb/学习`），每个库 init 一次即自动登记。`libraries` 一览全部库，`use` 按名称切换。
6. **跨库检索**：用户没指明在哪个库里找、或明确说"全部库都搜一下" → `search "<问题>" --all`。返回结果里每个 hit 都带 `kb`（来源库名称），作答时连同文件名一起标注。

## 行为约定

- 用户说"建个知识库"但没给目录 → 问一句想放哪，别自己造目录。
- 登记了多个库且用户没指定检索范围时，优先 `search --all`，并在答案里注明每条结果来自哪个库。
- `search` 返回的是结构化 JSON，直接解析；不要把原始 JSON 整段贴给用户，用人话总结 + 标注来源文件。
- 检索结果为空或分数都很低时，如实说"库里没有相关内容"，不要编造。
- `remove` 只删索引不删原文件；`forget` 只删注册表登记不删任何文件；用户要删原文件时另行确认。
- 所有数据都在 `<知识库目录>/.knowledge-base/index.sqlite`，换机迁移直接拷贝整个知识库目录即可；注册表只存路径和名称，换机后重新 init 一遍即可收编。
